### Corrections

- **Scope D closure claim (gap-closure merge [#253](https://github.com/High-Velocity-Decisions/sentient-rs/pull/253) / `11b165f`) was incorrect — re-opened, not re-closed.** That merge's commit message and this CHANGELOG's own "Features" entry below (`*(legacy)* AWS Greengrass backwards-compat...`) claimed Scope D (Greengrass backwards-compat) closed. Verification (`docs/gap-analysis-meteor-parity.md`, 2026-07-16 re-verification) found otherwise: `HostTap::Greengrass`'s dispatch arm in `impl-app/src/host/impl_host_tap.rs` was a no-op trace-log stub that never calls `tap.offer()`, so `legacy/#` never received a publish in the shipped binary — and, independently, the legacy schema transform diverges field-by-field from the real `example/aws` baseline (topic shape, field names, array-vs-flat cell/temperature keys, location flattening). GitHub issues [#256](https://github.com/High-Velocity-Decisions/sentient-rs/issues/256)–[#270](https://github.com/High-Velocity-Decisions/sentient-rs/issues/270) track the findings from this re-verification, including [#269](https://github.com/High-Velocity-Decisions/sentient-rs/issues/269) (the "claimed-vs-actual" gap-class retrospective this incident prompted). The original entry below is left intact, not deleted — this correction is the authoritative status update. **Scope D closure is re-claimed only when a wave-2 sinkset end-to-end test proves the full production dispatch path (not a renderer-only test that bypasses `HostTap`), per issue #269.** *(Path note, 2026-07-25: `impl_host_tap.rs` has since moved twice — externalized to `bin-rpi-platform` under ADR 0009, then reorganized to `crates/bin/rpi-platform/src/impl_host_tap.rs` under #384/385.)*
- **Meshtastic fault-forwarding regression closed (#386, #387).** `docs/reports/gap-analysis-meteor-parity.md`'s "faults are never forwarded over mesh at all — a genuine regression" finding (lines 29/156/217) is fixed: the mesh codec's `CondenseInput` now carries an optional `CanonicalFault` (JSON key `"f"`, a bitmask; bit 0 = `high_voltage_protection`), and the Pi forwards `TapEvent::Fault` to mesh immediately using the last cached reading for that DIP. Field-hardware validation (HIL against a real Meshtastic radio) has not happened yet — treat this as implemented, not verified on real hardware.
- **ADR 0006 (Meshtastic hand-rolled protobuf framing) superseded — its status banner, crate path, and one core assumption were all stale or wrong.** The banner claimed `impl_frame.rs` was a 2-3 line stub with no encoder and no golden tests; it is now a full encoder (`crates/lib-net/src/mesh/impl_frame.rs`) with byte-level golden tests. The record pointed at the pre-#287 `crates/lib-mesh/src/` path; the module lives at `crates/lib-net/src/mesh/`. Most significantly, the ADR's protobuf field numbers are now **verified** against `meshtastic/protobufs` @ master (its own revisit trigger is met) — and its `MeshPacket.to`-omitted-means-broadcast assumption is **falsified**: `meshtastic/firmware`'s `Router::sendLocal()` logs an error on `to == 0` and no firmware path rewrites it to `NODENUM_BROADCAST`, so frames sent before this fix were likely never delivered at all. The ADR's documented fallback ("swap in the real `meshtastic` crate, or `prost` + the pinned upstream `.proto` files") is also corrected: both `meshtastic/rust` and `meshtastic/protobufs` are **GPL-3.0**, making that fallback a copyleft ingestion event for a proprietary binary that the original record never weighed — `micropb` (MIT/Apache, no_std/no-alloc) from a locally re-declared minimal `.proto` is the defensible fallback if hand-rolling ever needs replacing. See `docs/decisions/0006-meshtastic-protobuf-approach.md` (superseded) and the new `docs/decisions/0012-delight-features-scope-and-seams.md`.

### Features

- *(dds)* DDS/RTPS transport beside MQTT on the Pi — RTPS/UDP, IPv6 (`ff02::1234` multicast + unicast), domain 0, XCDR2 (`D_CDR2_LE`) via `dust_dds` 0.15.0, config-gated (`[dds]`, off by default, byte-identical MQTT/JSON behavior when absent) (story [#321](https://github.com/High-Velocity-Decisions/sentient-rs/issues/321), WP1-WP7, [#322](https://github.com/High-Velocity-Decisions/sentient-rs/issues/322)-[#325](https://github.com/High-Velocity-Decisions/sentient-rs/issues/325))
  - `dust_dds` vendored (`vendor/dust_dds`, `[patch.crates-io]` path override) with a surgical 2-file rule-(12) NEXTINT patch (DDS-XTypes 1.3 §7.4.3.5.3 rule (12); disputes `eclipse-cyclonedds/cyclonedds-cxx#218` and OMG erratum `DDSXTY14-56`; `vendor/dust_dds/PATCHES.md`, upstream PR drafted). The chain serializer (`lib-tms::cdr`) adopted rule (12) too, so chain bytes match wire bytes again.
  - Interop verified against **stock, unmodified CycloneDDS 11.0.1** — official `cyclonedds` Python CLI tools in a `deploy/dds-conformance/` podman-compose harness plus a CI `dds-interop` lane: `cyclonedds ls` conformance (domain 0, bare CamelCase topics, QoS, `USER_DATA=deviceId`); live delivery + decode end-to-end; all 11 committed golden XCDR2 payloads accepted by the stock decoder (11/11); `@optional` presence-flag encoding empirically arbitrated both directions with CycloneDDS (no code change — the spec-literal boolean form already matched).
  - The 8 named D.5 QoS profiles wired per topic (`PublishLast` TRANSIENT_LOCAL/RELIABLE/KEEP_LAST 1, `Reply` RELIABLE/KEEP_LAST 128, telemetry BestEffort/Volatile), `USER_DATA=deviceId` on every writer; TRANSIENT_LOCAL late-joiner replay and `Reply` KEEP_LAST 128 depth exercised live in `test-e2e/tests/dds_interop_e2e.rs`.
  - Acceptance coverage: `rtps_spec.feature` (10 confirmed wire-format scenarios, incl. rule-(12)) and the `tms_spec_compliance.feature` `@dds-out-of-scope` carve-out now states the DDS posture explicitly.
  - Honest gaps recorded in `docs/tms-compliance.md` §7.1: only 3 of 10 publish topics (`Heartbeat`, `DcMeasurementUpdate`, `DcLoadSharingState`) plus the `Reply` path have a live DDS writer today — the other 7 are blocked on a `dust_dds_derive` `@optional` gap ([#332](https://github.com/High-Velocity-Decisions/sentient-rs/issues/332)); full-model XCDR2 wire validity is proven regardless, by the byte-oracle chain. `dust_dds` propagates no XTypes `TypeInformation` (stock `typeof`/`subscribe` type discovery is blind; SEDP discovery works). The MCU stays MQTT/JSON-only — DDS is Pi-only (MCU feasibility spike NO-GO on the 64 KB substrate, [#328](https://github.com/High-Velocity-Decisions/sentient-rs/issues/328)).
