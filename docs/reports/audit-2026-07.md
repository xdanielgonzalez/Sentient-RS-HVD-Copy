# Project Audit — July 2026

Full-project audit of `sentient-rs` against eight dimensions: goal/implementation fit, test
attestation (positive/negative/edge), code maintainability, CI pipeline shape
(gate → dev → UAT → production), IoT security posture, security boundaries in code,
documentation coverage (security, deployment, development, performance, compliance), and
Rust performance/memory practice. Conducted 2026-07-15 at base commit `771fd20` on branch
`claude/project-audit-cleanup-x6av8y`; three independent deep-exploration passes
(goals/docs, tests/CI, security/quality), one implementation-planning pass, and an
adversarial advisory review that overturned one planned change and reshaped three others
(§ Advisory record).

**Verdict in one paragraph.** The codebase is in unusually good hygiene for its age — two
TODOs in the whole crate tree, an empty type/impl-smell baseline, exemplary defensive
parsing with fuzz + property coverage, disciplined `no_std` memory practice, and a real
staged CI ladder. The material findings are of a different kind: **two contract scopes are
unimplemented** (A: microSD logging; D: Greengrass backwards-compat), **the entire
Zephyr/MCU CI lane is dark** (#191), several **testing instruments exist but never run**
(the Miri aliasing oracle, the UAT Robot e2e), and the docs contain **link rot and claims
that contradict the source**. Most of these were fixed on this branch; the rest are
dispositioned below.

## 2. Test attestation (positive / negative / edge)

**Strong where it exists.** `lib-parse` hardening suite asserts typed errors for corrupt
checksums, LENID mismatches, non-hex INFO, oversized INFO (bounded error, not panic), plus
proptests that the parser is *total* (`parse_never_panics`, single-byte mutation sweep).
`lib-link`'s broker tests use guard-byte canaries and exhaustive payload-size boundary
sweeps. `impl-app/tests/run_cycle.rs` covers failure counting, recovery, backoff-to-cap,
health streaks. Fuzzing: 3 libfuzzer targets + checked-in corpus replay. Mutation testing
weekly on `lib-parse`/`lib-security`.

**Gaps found (and their dispositions):**
- Thin crates lacked negative/edge coverage: `lib-channel` (4 tests, one of which was
  vacuous — an assertion ending in `|| true`), `lib-schema` (1 file), `lib-mqtt` (3),
  `lib-preflight` (5) → **hardened on this branch** (boundary matrices, truncation sweeps,
  per-flag fault sweeps, overflow caps). One deliberate skip: `lib-mqtt`'s
  negative-health streak test (2 failures healthy, 3rd flips) is unreachable without a
  production change — `LocalBroker` exposes no stop/shutdown handle (rumqttd's router
  thread runs forever) — recorded as S3 in the appendix rather than forced.
- `lib-channel`'s `packed` feature was enabled by **no** workspace consumer — its codec was
  never even compiled by CI → **wired into `just test` on this branch**.
- The purpose-built Miri Stacked-Borrows oracle (`broker_pump_aliasing_miri.rs`) had no
  runner anywhere → **`just miri` recipe + weekly CI lane added on this branch**.
- `test-e2e` and `test-acceptance` each ran **twice** per CI pass (plain workspace test +
  dedicated lane) → **deduplicated on this branch**.
- `bin/zephyr` firmware crate has zero tests and its only executable verification (Renode
  boot smoke) is disabled with #191 → partially unblocked by the west fix on this branch;
  re-enable steps documented in `production.yml`.
- Zero doctests execute (all fences ` ```ignore `/` ```text `) — noted, deliberately not
  converted (most sit on `no_std` crates where doctest scaffolding needs std context).
- Loom: unused. The concurrency-sensitive statics on the MCU are single-thread-owned by
  design; Miri covers the aliasing pattern. Recommendation R6 below.

## 3. Rust code maintainability

Excellent baseline: 2 TODOs repo-wide (`lib-io/src/embassy_uart.rs:123,127` — board-crate
hooks); zero `unimplemented!`/`todo!`; empty typeimpl ratchet baseline with a green audit;
consistent typed error enums per boundary; `anyhow` confined to the binary/host feature.
Workspace lints deny `unwrap`/`expect`/`panic` in production code (tests opt out
explicitly). Ten crates `#![forbid(unsafe_code)]`; after this branch, `bin-rpi` and
`lib-preflight` join them (the latter after rewriting its test executor helper with
`Waker::noop()` + `pin!`).

## 4. CI pipeline shape

The requested gate → dev → UAT → production ladder **exists and is real**:

```
PR    → ci.yml   lint gate → {test, security, supply-chain, quality}     (pull_request)
merge → uat.yml  build → QEMU boot-preflight UAT → promote (auto-cut)    (push: main)
          ↳ production.yml  validate-signing → build/sysext → signed PRE-RELEASE candidate vYYYY.MMDD.<run_id>
approve → promote.yml  (manual approval gate) → flip the SAME candidate to a FULL release
                        (same version, same UAT-tested assets — no rebuild, no re-sign)
tag   → production.yml  validate-signing → build/sysext → signed release  (v*.*.* push, alt path)
        image.yml (path-filtered) → _yocto.yml golden store — feeds UAT + production
```

Release lifecycle: every green merge auto-cuts a dated **pre-release candidate** (self-signed ⇒
pre-release tier). A reviewer promotes a blessed candidate to a **full release** via `promote.yml`,
gated on a **manual approval** (`trstringer/manual-approval` — native environment
required-reviewers aren't available for private repos on the Team plan) — reusing the exact version +
the exact signed artifacts that passed UAT (an in-place `prerelease → false` flip, not a rebuild).

Strengths: single fast lint gate fanning out; supply-chain deliberately not downstream of
tests; complete concurrency groups; correct cancel semantics; SHA-pinned actions; zizmor
workflow audit; sccache/NFS + MinIO sstate caching.

Weaknesses found → dispositions:
- **No Zephyr/west CI runs at all** (#191 topdir break; `_emulation.yml` orphaned; two
  `if: false` jobs) → root cause fixed on this branch (west manifest + workflow rewrite)
  and **proven locally with west 1.5.0**: `west init -l bin/zephyr` → topdir `bin/`,
  `manifest.path = zephyr`, and a real bounded `west update --narrow -o=--depth=1`
  landing `zephyr` at `bin/zephyr-rtos` (no collision with the app) and
  `zephyr-lang-rust` at `bin/modules/lang/rust`, with the full ~60-project import chain
  resolving under `west list`. Root `.gitignore` updated for the new layout. Jobs stay
  disabled pending one dependency unverifiable from here (the rebuilt
  `sentient-zephyr-builder` image, `production.yml` zephyr-job header) — re-enable is now
  a one-line flip, documented in place; a `workflow_dispatch` smoke run is recommended
  before wiring the jobs back into release `needs:`.
- UAT's headline Seplos→TMS→MQTT Robot e2e auto-skipped (no `distro/qemu/*.robot` existed) —
  the live UAT gate was boot-preflight only. Tracked: #156 — **suites landed on this branch**
  via the `feat/e2e-wiring` merge (`distro/qemu/e2e_telemetry.robot` + keywords + `uat.yml`
  wiring); first green UAT run is the remaining confirmation.
- `cosign sign-blob` is `continue-on-error` and SLSA attestation was removed (ARC OIDC
  breakage) — a green release can ship without its strongest provenance artifact. The
  signing *tier* honesty is already implemented (self-signed ⇒ forced pre-release with an
  explicit banner). Accepted policy; recommendation R3.
- Stale/false CI comments (11 dead `release.yml` refs, wrong `_quality.yml` MSRV note,
  wrong `ci.yml` emulation claim, two "doesn't exist yet" claims about files that exist) →
  **fixed on this branch**.
- Duplicated CMS/MinIO/parallelism/kas blocks → already being extracted by open PR #216;
  deliberately not touched here.
- semver job never gates (`continue-on-error`, no baseline) — known, documented.

## 5. IoT security posture

Measured against ETSI EN 303 645 / NIST 8259A expectations:

**Strong:** no hardcoded credentials (single env-var secret, fail-closed, 0600 rendering);
TLS with `bridge_insecure false` on the cloud path; default-drop nftables; exemplary
systemd sandboxing (`ProtectSystem=strict`, empty capability set, `MemoryDenyWriteExecute`,
syscall filter, device allow-list); read-only rootfs, locked root, no package
manager/SSH/debug in the image; KSPP kernel fragment + distro-wide PIE/RELRO; CMS-signed
binaries verified on device (`distro/deploy/verify-binary.sh` as `ExecStartPre`); SBOMs
(CycloneDX per binary, SPDX in image); cargo-audit/deny/vet + openssl banned; signed
`.wic` images with tier-honest releases.

**Findings → dispositions:**
- Committed TLS bring-up **private key** (`crates/lib-link/certs/bringup_key.der`) →
  **removed on this branch**; `TlsStage::new_client` now takes an explicit trust root,
  the identity is generated ephemerally per process by `test-kit::tls` (rcgen, ring
  backend — kept out of `bin/zephyr/Cargo.lock` and the firmware SBOM by design), and a
  rotation note was added to `docs/security.md`. Advisory confirmed it was test-tier only
  (no shipping binary embeds it) and that history rewrite is not warranted. One caveat:
  `cargo vet` cannot run in this sandbox (it resolves through the unreachable internal
  registry with no CLI override) — the `rcgen`/`yasna` exemptions in
  `supply-chain/config.toml` were added mechanically and **must be confirmed with
  `cargo vet --locked` on the HVD network before merge**.
- MCU network path is plaintext MQTT (bring-up tier, emulation only today) — untracked
  gap; recommendation R2.
- No mTLS anywhere (`with_no_client_auth()` both roles; cloud bridge is password-over-TLS)
  — recommendation R2; the TPM device-identity story (#170/#171) is the designed endpoint.
- Both brokers default to no CONNECT auth (mitigated: loopback-bound + nftables; token
  seam with signature-first verification exists in `lib-security`) — acceptable interim.
- Secure update chain: sysext app/base split exists; RAUC A/B (#160) and dm-verity (#204)
  tracked; RPi closed BootROM is documented accepted residual risk.
- No secret-scanning workflow exists — recommendation R4.

## 6. Security boundaries in code

Trust boundaries are explicitly modeled and mostly `forbid(unsafe_code)`:
byte-in/byte-out `TlsStage` that never touches sockets; pure `BrokerCore` fed by a thin
pump; pure `no_std` parsers on slices. The only network-input-reachable FFI is the MCU
broker pump (`broker_pump.rs`, since relocated to `bin/zephyr/platform/` in this branch) — bounded reads, length-validated,
fresh slice re-derivation per FFI call, fails closed on malformed input, and its aliasing
pattern has a dedicated Miri oracle (now actually executed weekly). The gap was
inconsistent `// SAFETY:` coverage on ~14 sibling FFI blocks
(`impl_zephyr_uart.rs`, `impl_zephyr_platform_core.rs`, `zephyr/mod.rs`) →
**documented on this branch** to the `broker_pump.rs` standard.

## 8. Rust performance & memory practice

Conforms to the embedded rules: canonical-not-serialized storage (`CanonicalReading` ring
arena; render-on-transmit into one reused buffer); large state deliberately in `.bss` with
measured stack-overflow rationale written at the site; `#[inline(never)]` frame-splitting
where match-arm frames diverge; ≤4 `.clone()` on the MCU hot path; heapless everywhere on
the `no_std` path; `panic="abort"` + `overflow-checks` on the shipping profile;
`opt-level="z"`, LTO, single codegen unit. MCU release profile leaves overflow-checks off
(size tradeoff, documented; parser uses wrapping/saturating arithmetic deliberately).
One inconsistency found (stack-size comment vs configured value in `bin/zephyr/emu-e2e.conf`)
→ **comment reconciled on this branch**; the value itself must only move with fresh
measurement.

## Advisory record (bias counteraction)

An adversarial advisory reviewed the planned cleanup before execution. Outcomes:
- **REJECTED — feature-gating MCU diagnostics.** The plan proposed a default-off `diag`
  cargo feature for the "not meant to ship" log lines and T3STACK probes. The advisory
  showed the probes are the active instrument for a stack diet the repo's own config
  says is unconfirmed, the architecture's probe lever is Kconfig (not cargo features),
  and there is no Zephyr CI to catch cfg regressions. Dropped; revisit only after #191
  CI is green and the broker stack diet is confirmed (then via the existing Kconfig path).
- **RESHAPED — key remediation.** "Keep cert, regenerate key" was discarded as
  cryptographically incoherent; the generator dependency was confined to test-support
  crates so it can never reach the firmware lockfile/SBOM.
- **RESHAPED — #191 re-enable.** Local verification cannot prove the rebuilt
  zephyr-builder image exists, so the `if: false` flips were withheld; the fix landed
  with truthful re-enable instructions instead of risking a red release lane.
- **RESHAPED — scope.** Confirmed contract features stay report-only; confirmed the
  double-run exclusion also applies to `test-acceptance`; flagged the stack-size
  comment/value mismatch this report now records.
- **Review-split recommendation.** The advisory recommended landing this work as three
  reviewable units (west/CI fix · key remediation · docs/tests bulk). Commits on this
  branch are grouped accordingly so maintainers can split or cherry-pick.

## Consolidated recommendations (prioritized)

- **R1 — Re-enable the Zephyr lane** (small): confirm the rebuilt `sentient-zephyr-builder`
  image, flip the two `if: false` lines in `production.yml`, observe one green run, then
  re-add both jobs to the release `needs:`. The west fix on this branch removed the root
  cause. Then close #191.
- **R2 — MCU transport security + mTLS** (large, design): the owned MCU path is plaintext
  and no leg uses mutual TLS. The endpoint is the TPM device-identity story (#170/#171);
  until then, document the emulation-tier plaintext status in `docs/security.md` threat
  model terms.
- **R3 — Make provenance non-optional** (small): once ARC OIDC is stable, drop
  `continue-on-error` from cosign sign-blob so a full-tier release cannot publish without
  its bundle; revisit SLSA attestation when the org plan allows.
- **R4 — Add secret scanning** (small): a gitleaks/secret-scan job in `_supply-chain.yml`;
  note DER-binary keys evade most scanners — pair with a repo rule that test identities
  are generated, never committed.
- **R5 — Author `docs/performance.md`** (medium): consolidate the SRAM/stack budget, frame
  measurement method (`-Zemit-stack-sizes`, thread analyzer), RPi telemetry-loop latency
  expectations, and the poll-cadence/soft-real-time posture.
- **R6 — UAT Robot e2e (#156)** (medium): the `distro/qemu/*.robot` suites are the missing
  attestation for the full Seplos→TMS→MQTT path on the shipping image; the harness script
  already exists.
- **R7 — Coverage ratchet** (small): after this branch's tests land, read tarpaulin's new
  percentage and raise `--fail-under` accordingly (kept out of this PR to decouple failure
  modes).
- **R8 — Close the contract gap deliberately** (large): schedule Scopes A and D as proper
  slices with acceptance criteria in `test-acceptance` (#52–#57), not cleanup add-ons.
